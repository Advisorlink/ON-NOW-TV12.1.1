# RCA — GET /api/sportshub/highlights returns error in production

## Problem statement
`GET https://onnowhub.com/api/sportshub/highlights?home=Seattle%20Seahawks&away=Kansas%20City%20Chiefs&startMs=1792974000000&league=NFL` reported as HTTP 500 in production, while the same request returns 200 (official NFL video, ~1.5s) on the preview backend. Code lives in `/app/backend/sports_highlights.py` (preview).

## Root cause — the feature is NOT deployed to production (route does not exist → 404)
The reported 500 is NOT a KeyError, NOT yt-dlp, and NOT a YouTube bot-block. The real behavior at the production backend is **404 Not Found**, because the `/api/sportshub/highlights` route is not registered in the deployed code at all.

### Evidence
1. **Production logged the exact request as 404**, not 500:
   `INFO: 172.69.58.213:0 - "GET /api/sportshub/highlights?home=Seattle%20Seahawks&away=Kansas%20City%20Chiefs&startMs=1792974000000&league=NFL HTTP/1.1" 404 Not Found`
   (172.69.58.213 is a Cloudflare egress IP = the onnowhub.com worker. Any 500 the user saw is the worker/edge wrapping the backend 404; backend ground truth is 404.)
2. **`sports_highlights.py` does not exist in the deployed source.** `ls /app/scratch/backend/` on the active run's source shows: backup.py, epg_cache.py, espn.py, instant_bundle.py, requirements.txt, server.py, sportsdb.py, tests, watch_party.py, xtream.py — no sports_highlights.py. A tree-wide grep for `sportshub|sports_highlights|SPORTS_YOUTUBE|ytsearch` finds nothing matching the highlights feature.
3. **`server.py` registers no such route.** The `api = APIRouter(prefix="/api")` route list contains `POST /api/sports/find` and `GET /api/trailer-stream/{youtube_id}` but NO `/sportshub/highlights`. (yt-dlp==2026.3.17 IS in requirements.txt and is used by the trailer feature, so yt-dlp is not the issue.)
4. The active production run is `24c618f6` (redeploy, 2026-10-27 04:46 UTC). The preview that returns 200 contains the feature added after that deploy, so the production image predates it.

## Five SPORTS_* env vars in production — ANSWER: all five are ABSENT
`list_secrets` on the active run returns these keys only: APK_GITHUB_REPO, CORS_ORIGINS, DB_NAME, EMERGENT_LLM_KEY, ENABLE_HEALTH_CHECK, INTEGRATION_PROXY_URL, LIVETV_DEFAULT_PASSWORD, LIVETV_DEFAULT_USERNAME, LIVETV_HOST, LIVETV_PORT, LIVETV_SCHEME, MONGO_URL, REACT_APP_BACKEND_URL, TMDB_BEARER_TOKEN, WDS_SOCKET_PORT, XTREAM_ADMIN_TOKEN.

None of `SPORTS_YOUTUBE_OEMBED_URL`, `SPORTS_YOUTUBE_WATCH_URL`, `SPORTS_YOUTUBE_EMBED_ORIGIN`, `SPORTS_EMBED_ORIGIN`, `SPORTS_YOUTUBE_IFRAME_API_URL` exist in production.

## Consequence / why this matters for the fix
Because `sports_highlights.py` reads these via `os.environ[...]` (raises KeyError if missing): once the feature IS deployed, if the five SPORTS_* secrets are still absent in production the endpoint will then start returning a REAL 500 (KeyError). So both actions below are needed together.

## Fixes
1. **Code / redeploy (E1 + user):** The new backend code (sports_highlights.py + its router wiring in server.py) only exists in preview. Deploy the latest code to production so the route is registered.
2. **User → Secrets tab (before/at that deploy):** Add the five env vars `SPORTS_YOUTUBE_OEMBED_URL`, `SPORTS_YOUTUBE_WATCH_URL`, `SPORTS_YOUTUBE_EMBED_ORIGIN`, `SPORTS_EMBED_ORIGIN`, `SPORTS_YOUTUBE_IFRAME_API_URL` with the same values used in preview. Without them the deployed endpoint will 500 on KeyError.

## Notes / not reproduced
- yt-dlp datacenter-IP bot-block ("Sign in to confirm you're not a bot") could not be tested — the request never reaches the yt-dlp path in production (route absent). It remains a possible separate risk once deployed, since production egresses from datacenter IPs, but there is no evidence of it here.
- Secret states are from the ACTIVE (serving) run.
